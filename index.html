🌐 Troubleshooting de Redes de Computadores

Simulação e diagnóstico de 5 situações comuns em redes locais — causas, comandos e soluções.

ObjetivoMétodoComandos 1 Sem internet2 IP incorreto3 DNS4 Cabo5 Conflito IPRepositório

Objetivo

Desenvolver a capacidade de identificar, analisar e solucionar problemas comuns de redes de computadores, utilizando procedimentos e ferramentas de diagnóstico. Para cada situação o projeto descreve o que está acontecendo, as causas prováveis, os comandos para identificar o problema e a solução.

Método de diagnóstico

Analise sempre de baixo para cima: o primeiro passo que falhar mostra onde está o problema.

1 Cabo / Wi-Fi→2 IP válido→3 Gateway→4 Internet por IP→5 DNS

Comandos e ferramentas

ComandoFinalidade
ipconfig /all · ip aMostra IP, máscara, gateway, DNS, MAC e se o DHCP está ativo.
ipconfig /release e /renewLibera e solicita um novo IP ao servidor DHCP.
ipconfig /flushdnsLimpa o cache de DNS.
pingTesta conectividade e mede latência e perda de pacotes.
tracert · tracerouteMostra os saltos até o destino e onde o caminho para.
nslookupConsulta DNS e mostra qual servidor respondeu.
arp -aLista a relação IP ↔ MAC (útil para achar conflitos).
route print · ip routeExibe a tabela de rotas e o gateway padrão.
netstat -anLista conexões e portas em uso.
nbtstat -a <IP>Identifica nome e MAC de um host da rede.

Situações analisadas

1. Computador sem acesso à internet

O que está acontecendo

As páginas não carregam no navegador, embora o computador possa estar conectado à rede local.

Possíveis causas

  • Roteador/modem sem sinal do provedor
  • Gateway incorreto ou ausente
  • Falha de DHCP ou de DNS
  • Cabo ou Wi-Fi com problema
  • Firewall ou proxy

Diagnóstico

ipconfig /all
ping 127.0.0.1        # pilha TCP/IP local
ping <gateway>        # alcança o roteador?
ping 8.8.8.8          # alcança a internet por IP?
ping google.com       # resolve nomes?
tracert 8.8.8.8       # em qual salto para?

Gateway não responde → problema na rede local. Gateway responde e 8.8.8.8 não → roteador/provedor. 8.8.8.8 responde e o nome não → DNS.

Solução

  1. Reiniciar modem e roteador (30 s desligados).
  2. Conferir cabos e Wi-Fi.
  3. Executar ipconfig /release e ipconfig /renew.
  4. Corrigir gateway/DNS ou voltar ao IP automático.
  5. Se só o roteador responde, contatar o provedor.

2. Endereço IP incorreto

O que está acontecendo

A máquina tem um IP fora da faixa da rede ou recebeu um endereço APIPA (169.254.x.x), sinal de que não encontrou o servidor DHCP.

Possíveis causas

  • IP, máscara ou gateway digitados errados
  • DHCP desligado ou sem endereços livres
  • Falha de cabo/Wi-Fi impedindo contato com o DHCP
  • Máquina em rede/VLAN errada

Diagnóstico

ipconfig /all    # IP na mesma faixa do gateway? DHCP ativo?
ping <gateway>   # sem resposta confirma o erro

Exemplo correto: IP 192.168.1.25, máscara 255.255.255.0, gateway 192.168.1.1.

Solução

  1. Corrigir a configuração manual ou escolher Obter endereço IP automaticamente.
  2. Executar ipconfig /release e ipconfig /renew.
  3. Verificar cabo, reiniciar roteador/DHCP e conferir o pool de endereços.

3. Problema de DNS

O que está acontecendo

O acesso por IP funciona (ping 8.8.8.8), mas sites por nome não abrem.

Possíveis causas

  • Servidor DNS incorreto ou fora do ar
  • Cache DNS corrompido
  • DNS do roteador com defeito
  • Arquivo hosts alterado
  • Bloqueio da porta 53 no firewall

Diagnóstico

ping 8.8.8.8                  # funciona → internet OK
ping google.com               # falha → suspeita de DNS
nslookup google.com           # servidor usado e resposta
nslookup google.com 8.8.8.8   # testa com outro DNS
ipconfig /all                 # DNS configurados

Se funciona com 8.8.8.8 e não com o DNS atual, o DNS configurado é o culpado.

Solução

  1. ipconfig /flushdns
  2. Trocar o DNS para 8.8.8.8 / 8.8.4.4 ou 1.1.1.1.
  3. Reiniciar o roteador.
  4. Verificar o arquivo hosts.

4. Cabo de rede desconectado ou com defeito

O que está acontecendo

O ícone de rede mostra um “X” e a mensagem “Cabo de rede desconectado”, ou a conexão cai, fica lenta ou negocia só 10 Mbps.

Possíveis causas

  • Cabo solto ou rompido
  • Conector RJ-45 mal crimpado ou oxidado
  • Porta do switch ou placa de rede com defeito
  • Cabo acima de 100 m ou com interferência
  • Placa de rede desabilitada

Diagnóstico

Verificar os LEDs da placa e da porta do switch (apagados = sem link), trocar o cabo, testar outra porta e usar um testador de cabos.

ipconfig /all     # "Mídia desconectada" confirma falta de link
ip link show      # Linux: NO-CARRIER / DOWN
ping <gateway>    # sem resposta

Solução

  1. Reconectar firmemente as duas pontas.
  2. Trocar o cabo ou refazer o conector RJ-45.
  3. Usar outra porta do switch.
  4. Habilitar ou reinstalar o driver da placa.
  5. Se necessário, trocar a placa ou usar adaptador USB.

5. Conflito de endereço IP

O que está acontecendo

Surge o aviso “Há um conflito de endereço IP”. A conexão fica intermitente e um dos dispositivos pode perder a rede.

Possíveis causas

  • Dois dispositivos com o mesmo IP fixo
  • IP fixo dentro do pool do DHCP
  • Dois servidores DHCP na rede
  • Máquina voltando de suspensão com IP antigo

Diagnóstico

ipconfig /all          # anote seu IP e MAC
arp -a                 # MAC associado ao IP em disputa
ping <IP em conflito>  # outro host responde?
nbtstat -a <IP>        # nome/MAC do outro dispositivo

Se o IP continua respondendo com a sua máquina desconectada, outro dispositivo o está usando. O MAC do arp -a ajuda a localizá-lo.

Solução

  1. Mudar o IP de um dos dispositivos (fora do pool DHCP) ou usar DHCP.
  2. Executar ipconfig /release e ipconfig /renew.
  3. Criar reserva de DHCP (IP fixo por MAC) para equipamentos importantes.
  4. Remover servidores DHCP duplicados.
  5. Documentar as faixas de IP fixos e dinâmicos.
